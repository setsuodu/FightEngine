# FightEngine 开发路线图

> 目标：先做出「本地可打、可调帧数据、状态可回滚」的格斗 MVP；联机与豪华表现往后放。
>
> 约束见 [CONVENTIONS.md](./CONVENTIONS.md)。Issue 只开「当前里程碑」，本文不当看板。

---

## MVP 定义（可玩切片）

两个方块/简易角色，本地 1v1：

- 走、蹲、跳（可选）
- 1～2 个攻击 + hit/hurtbox
- 受击、硬直、简单 hitstop
- 固定 60Hz 确定性逻辑
- 编辑器能改参数并热重载
- 状态可 Save/Load（为 GGPO 留钩子）

## P0 — 打通「能打」的最小闭环

**目标：本地两个实体能互相打中，逻辑全在 Sim 里。**

| 项 | 内容 | 验收 |
|------|------|------|
| 定点数 | `Fixed` 补加减乘除、Clamp、FromFloat（仅工具） | Sim 内无 `float` 运算 |
| 输入缓冲 | 环形缓冲 8～15 帧；方向+键 合成 | 能扫简单 236+P 或先做「按住出招」 |
| 实体与框 | Fighter：位姿、状态枚举、HP；多 hit/hurt 矩形 | Viewport 画出 body/hit/hurt |
| 状态机 v0 | Idle / Move / Attack / HitStun / BlockStun | 攻击中不能乱取消 |
| 碰撞 | 框对框，命中写结果事件（不直接播特效） | A 打中 B → B 进 HitStun、掉血 |
| 表现解耦 | 逻辑事件队列 → 渲染只读状态+事件 | 重模拟不叠音效（先可无声） |

**P0 结束应有：** WASD/方向键互殴，打中有硬直，Reset/Snapshot 正常，热重载不丢局内状态。

**主要改动：** `game/`、`engine/core/fixed.*`、Viewport DebugDraw（尽量不写死 `DemoGameState` 布局）。

---

## P1 — 帧数据与编辑器生产力

**目标：调手感不用改代码重编（或只热重载 game）。**

| 项 | 内容 | 验收 |
|------|------|------|
| 招式表 | startup / active / recovery、伤害、取消窗口 | 数据驱动，不写死在 Tick 分支 |
| 框关帧 | 每招每帧 hit/hurt 可不同 | Viewport 按当前帧显示框 |
| ImGui 帧数据面板 | 改数字、看时间轴、选当前招 | 改完立刻影响下一招 |
| 训练模式 | 无限血、固定对手、一键重置 | 调招不靠重开进程 |
| DebugDraw 契约 | GameAPI 输出框/骨点，Renderer 只画 | 引擎不再写死 Demo 布局 |

**P1 结束应有：** 调一招的帧数/框在编辑器里完成，Viewport 所见即所撞。

---

## P2 — 回滚就绪（仍可先单机）

**目标：状态与模拟达到 GGPO 可接程度。**

| 项 | 内容 | 验收 |
|------|------|------|
| 状态体检 | 全状态 POD、无指针、尺寸稳定、checksum | 同输入两遍跑 checksum 一致 |
| 确定性 RNG | RNG 状态进 StateArena | 随机命中效果可复现 |
| 输入序列回放 | 录输入 → 重放画面一致 | 回放工具面板 |
| 表现去重 | 音效/震屏带 `frame+id`，确认帧才触发 | 人为 rewind 不炸音 |
| `INetSession` 空接 | Save/Load/Advance 接到 StateArena | 接口能单测，不必真联网 |

**P2 结束应有：** 自动测试「同输入 → 同 checksum」；回放无漂移。

> **没做完 P2 不要急着接 GGPO。**

---

## P3 — 本地完整 MVP 手感

**目标：像一个能给别人试的 mini 格斗 Demo。**

| 项 | 内容 | 验收 |
|------|------|------|
| 推挤 / 边角 | 简单 body 推挤、墙 | 两人贴在一起行为稳定 |
| Hitstop / 击退 | 定点数位移曲线 | 打中有停顿和位移 |
| 防御 | 站防/蹲防、GuardStun | 能防、能被抓（可后做投） |
| 资源条 | 血条 UI（ImGui 或 RT 上画） | 可读 |
| 音频最小 | miniaudio，命中/受击各一音 | 仅确认帧播放 |
| 2 套角色数据 | 可用同一骨架不同帧表 | 选人可 hack 写死 |

**P3 结束应有：** 本地 1v1 打完一轮，手感可展示，包体仍是轻量 editor+game。

---

## P4 — 联机与内容管线（后 MVP）

**目标：从「能演示」到「能对战/能扩内容」。**

| 项 | 内容 | 验收 |
|------|------|------|
| GGPO/Gekko 接入 | 真回滚 1v1（局域网优先） | 延迟/丢包下可打，desync 有 log |
| NAT/主机 | 先局域网；公网另接 Steam/自建 | 文档写清范围 |
| 资源/cooker | 精灵或简单 mesh 管线、句柄 | 换皮不改代码 |
| 动画 | 帧动画或骨架采样 `IAnimation` | 攻击与帧数据对齐 |
| 反射/属性面板 | 通用改组件字段 | 少写专用面板 |
| 构建/发行 | tag Release；符号/崩溃后续 | 一条命令出可分发 zip |

---

## 建议顺序

```text
P0 能打中
 → P1 能调帧/框
 → P2 能证明确定性
 → P3 能给人试打
 → P4 能联机 + 管线
```

---

## 刻意不进 MVP 的

- 完整材质/后处理/渲染图
- 3D 蒙皮与复杂镜头（除非确定做 3D）
- 匹配服务器、排位、回放分享社区
- 反射系统大而全、通用序列化框架

## Issue 开法

1. 本文 = 地图，改方向只改这一份。
2. GitHub Issue **只开当前里程碑**（现在应该是 P0），每条对应可合并的一小刀，写清验收。
3. P0 收完再开 P1，不要一次性把 P0～P4 全部开成 Issue。
